PIXORA — REAL BACKEND REPAIR

This ZIP is a repaired version of the Pixora project. The previous build had client/schema mismatches that caused:
- User not found in chat
- posts/author_id relationship errors
- profiles.name search errors
- Bucket not found when uploading photos
- notifications/messages not being wired consistently

WHAT WAS FIXED IN THE CODE
1. Removed PostgREST embedded profile relationships from posts, stories, messages and notifications. Profiles are loaded separately, so the app no longer depends on a stale schema-cache relationship.
2. Standardized profile columns: name, username, bio, avatar_url, cover_url, account_type.
3. Standardized notification columns: recipient_id, actor_id, type, message, post_id, created_at, read_at.
4. Fixed chat recipient lookup and message sending.
5. Fixed conversation list and unread-message counting.
6. Fixed in-app notifications generated by messages, follows and likes.
7. Fixed notification read state.
8. Fixed image uploads to the pixora-media bucket.
9. Added a database repair/install SQL file that safely adds missing columns, foreign keys, policies, triggers, storage bucket and realtime configuration.
10. Kept the existing Pixora UI instead of replacing it with a fake/demo backend.

ONE REQUIRED BACKEND STEP
Because a GitHub Pages website cannot create Supabase tables, triggers or storage buckets with the public client key, you must run schema.sql in your Supabase SQL Editor once.

After running it:
- create/login with two Pixora accounts
- search for the other account
- tap Message
- send a message
- open Notifications on the receiving account
- follow/unfollow the other account
- create a post with a photo

Do not skip schema.sql. Without the database repair, no ZIP can make a missing Supabase table, bucket or trigger exist.
